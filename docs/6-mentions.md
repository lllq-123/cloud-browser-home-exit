# 第 6 步：被@了怎么知道

> 这一步做完：有人@小机、回复小机，它能发现、能回。

小机不会自己醒来。得有个东西定时去看一眼通知页，发现新的，再把小机叫起来。我们家管这个东西叫**看门狗**。它的代码绑着我们家自己的心跳和叫醒队列，没法原样公开；这里把它**怎么做的**写清楚，再给一个不需要任何基础设施的手动版。

## 它靠的命令

```bash
CI=1 opencli xiaohongshu mentions --limit 20 -f json
```

这条读的是小机号通知页「评论和@」那一栏最近 20 条。`-f json` 的每条带：通知编号（`id`，19 位数字）、类型、谁（`user_id` + `nickname`）、哪篇帖子（`note_id`，以及可以直接打开的 `note_url`）、评论内容、**评论编号（`comment_id`，24 位，回复要用它）**。

官方自带的 `notifications` 命令没有这些编号，所以我们自己写了一条。

它在常驻页里页内点进通知页，三四秒就回来，**不经过手机**；只有页面坏了才整页重开。还有一个副作用：打开通知页就等于「已读」，小机号 App 上的红点会被清掉。

## 我们家的看门狗是怎么跑的

1. **多久看一次**：cron 每小时一次，只在早 8 点到晚 11 点（`7 8-23 * * *`，启动后先随机等 0～60 秒）。夜里不看。以前是每 5 分钟一次，10 月 17 日改成了每小时——落落怀疑看得太勤是评论被审的原因之一，没证实，但慢一点没坏处。
2. **去重**：按通知编号记一个「见过的」列表（留最近 500 条）。第一次跑只记下现有的、不叫人；读到空列表时不更新（可能是页面没加载完）。
3. **认人**：只看用户编号，不看昵称、不看通知类型。我们家分两路：
   - **主人**@的、回复的 → 直接给当班的小机建一张「小红书」卡，到点叫醒它去回。
   - **别人**冲小机来的 → 先筛掉几类（小机自己的、平台 AI 的、楼中楼里回别人的、@ 了别人没 @ 小机的），剩下的建一张「等你放行」的卡，**永远不自动回**。主人在自己的面板里点一下才叫小机去回，3 天没放行就自动消失。
4. **叫醒后小机看到什么**：一段固定的说明 + 卡片正文。正文是：谁、干了什么、在哪篇帖子（链接）、评论原文、评论编号。小机先 `note` + `download` 看帖，`comments --with-replies` 看评论区，再决定怎么回，用 `comment --reply-to <评论编号>` 回。
5. **出错**：读通知连续失败 3 次发一次提醒（登录掉了、页面改版、浏览器挂了都会这样）；恢复了再说一声。

我们家这套的开关、放行按钮都在自己的 App 里，这一部分别人照不了。

## 手动版（什么都不用搭）

最简单的做法：**每次和小机聊天开头，让它先看一眼通知。**

> 「先跑一下 `mentions`，有没见过的通知就告诉我，然后我们再决定回不回。」

小机把见过的通知编号记在一个文件里（比如 `~/.xhs_seen_ids`），每次只报新的。这就是看门狗最核心的两步：读 + 去重。

## 定时版（你的小机有定时功能的话）

Claude Code、Codex、OpenClaw 这些工具有的自带定时任务或者「心跳」。原理一样：

1. 定时（我们家是每小时、夜里不跑）跑 `mentions`，和「见过的」文件对比。
2. 有新的，就把新通知的内容整理成一段话，用你的工具的办法把小机叫起来（或者推到你的聊天里）。
3. 小机回复时用 `comment --reply-to`，回完把通知编号记进「见过的」。

定时任务的环境和你在终端里不一样，两件事要做：入口脚本开头的 `NODE_BIN_DIR` 写死成 nvm 里 Node 22 的目录（定时任务里没有 nvm）；命令用绝对路径 `~/.local/bin/opencli`（定时任务的 PATH 里通常没有它）。

两条建议，都是我们家踩出来的：

- **别人的 @ 让人先看一眼再回。** 评论区什么人都有，让小机自动回陌生人，等于把一个能发言的 AI 交给路人指挥。我们家陌生人的卡永远等主人放行。
- **别太勤。** 一小时一次足够了。每 5 分钟盯着通知页刷，和「正常人」差得太远。
