# 验证范围与已知限制

整理日期：**2026-10-28**。

## 日用环境已有的证据

来自我们 2026-10-27 的使用记录和随后对实际文件的核对：

| 项目 | 观察结果 |
| --- | --- |
| 海外浏览器访问主站 | 当时从新加坡整页打开会跳到海外站，经国内一加出口可打开原站 |
| 出口隧道 | 海外服务器使用 chisel 1.12.0；日用是 HTTPS nginx 转到回环 chisel，再由一加提供反向 SOCKS5 |
| 浏览器分流 | 主站网页经一加；当时所需的主要数据接口仍可新加坡直连 |
| 常驻页操作 | 在已加载测试页中屏蔽主站请求后，受测的通知、推荐、搜索、帖子及评论读取仍能取数；这些操作没有新增主文档请求 |
| 回收与恢复 | 使用专门常驻会话并让清理任务保留它；页面需要重开时仍保留国内出口 |

这些观察支持的是特定时间、账号和环境下的方案，不证明所有海外地区、账号、接口都会相同，也不证明真实断开手机后每一个功能都能继续运行。

## 本仓库公开示例的验证方式

- chisel 安装资产名、版本、反向 SOCKS、认证文件 ACL 和指纹参数：核对官方发布及本机 1.12.0 帮助。
- PAC：检查语法和目标域名路由，确认主站走本机 SOCKS、其他域名直连。
- Markdown：检查相对文件链接、代码块语法、示例占位符及公开文件范围。
- systemd 示例通过静态 `systemd-analyze --user verify`；nginx 片段放入临时配置，通过 `nginx -t`。这些检查不启动服务，也不验证实际网络连接。
- OpenCLI 2.0.2 配方：核对 npm 元数据和官方 tag 源码，未安装新 CLI、未启动新的 daemon 或浏览器。

公开示例比我们原有日用配置增加了固定服务器密钥、客户端指纹校验和收窄的认证 ACL。它们来自 chisel 官方支持的配置，**没有把这套新示例替换到我们的日用服务，也未做一套全新设备的端到端安装**。

无 Root Termux 路线是可尝试的适配方案，尚未在干净手机上完成实测。Windows / macOS 可选择对应 chisel 二进制，但本仓库只提供 Linux 常驻服务模板。

## 已知边界

- 页面第一次打开、失效后恢复、整页刷新，依然可能需要国内设备在线。
- 某些主站图标或静态资源也走国内出口；不能把“没有主文档请求”说成“完全没有主站请求”。
- 保留标签页不会让网站登录永不过期，也不会让工具的绑定在重启后一定恢复。
- 我们自己的定制适配器有长列表滚动加载问题，大量评论读取也可能超时；本教程以正常小批量浏览为入口，不提供批量采集保证。
- 发帖、草稿、创作中心以及全部互动功能，不属于本教程完整验证范围。访问成功不代表发表内容的公开可见性。
- 网站若改为要求数据接口也从国内访问，就需要重新验证分流，常驻页不能消除这个前提。

本次公开整理没有改变现有家庭服务，没有发送测试评论或发表笔记。
